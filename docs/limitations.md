# Known Limitations

BrandGuardian is an MVP compliance workspace built for Round 2 judging with synthetic workspace data. The constraints below reflect observed behavior and design trade-offs in the codebase today:

1. **English-Only Analysis:** Both deterministic pattern checkers (`\b` word boundaries, English phrasing) and the LLM prompt (`ai-service/main.py`, `language: "en"` default) assume English-language copy. Non-English text is unsupported.
2. **Scoped Regex Fact Matching:** [`check_facts()`](../ai-service/main.py#L179-L203) uses regex patterns configured per row in `approved_facts.match_pattern` (with one capture group) compared against canonical `value`. Although `build_user_prompt()` now supplies compact active `APPROVED FACTS` and `APPROVED TERMINOLOGY` context to the LLM as an advisory net (`Unverified` `AI-generated`), deterministic fact checking only covers patterns matching configured regex templates—it does **not** guarantee exhaustive open-ended world fact verification.
3. **Best-Effort Small-LLM Tone & Claim Analysis:** Hosted inference uses Groq `openai/gpt-oss-20b` (`reasoning_effort="low"`, `LLM_TIMEOUT=30`; optional local mode `qwen2.5:3b` via Ollama). Nuanced `tone`, `messaging`, unpatterned facts, and unpatterned claims remain best-effort, are labeled **`Unverified`** when no matching workspace rule applies, carry **`AI-generated`**, and display an **`(estimate)`** confidence percentage.
4. **Heuristic Keyword Rules (`"guarantee"`, Comparative Superlatives):** While seeded rule matching in [`supabase/seed.sql`](../supabase/seed.sql) and [`supabase/migrations/0004_remediation_integrity_and_rpc.sql`](../supabase/migrations/0004_remediation_integrity_and_rpc.sql) now excludes `"best practices"` via negative lookahead (`best(?!\s+practices\b)`), any broad keyword-regex rule still evaluates phrasing locally without deep syntactic parsing; human `Reject` / `Dismiss` review remains essential.
5. **Unapplied SQL Migrations & Tests Pending `USER-RUN` Execution:** Migrations [`0003_audit_server_only.sql`](../supabase/migrations/0003_audit_server_only.sql) and [`0004_remediation_integrity_and_rpc.sql`](../supabase/migrations/0004_remediation_integrity_and_rpc.sql) (plus verification scripts `decision_rls.sql` and `remediation_checks.sql`) exist on disk and are **not yet applied** to Supabase. Until executed by the Project Owner (`USER-RUN`):
   - `POST /api/suggestions/[id]/decision` returns honest `HTTP 503` (missing `record_review_decision` RPC from `0004`).
   - Legacy `audit_insert` authenticated policy (`0001`), mutable post-review `documents.status`/`content` (`0002`), and non-validated DB `CHECK`s remain active until `0003` and `0004` run.
6. **Free-Tier Hosting Cold Starts & Vercel Serverless Function Timeout:** Deploying `ai-service` on Render or Railway free tiers incurs idle sleep cold starts unless `/health` or `/ready` is warmed beforehand ([`docs/deployment.md`](deployment.md)). [`web/app/api/review/route.ts`](../web/app/api/review/route.ts#L7) exports `maxDuration = 60` (`AbortSignal.timeout(50_000)`); Vercel projects must have `60s` execution enabled (Fluid Compute or Pro) so reviews do not hit a `10s` legacy timeout.
7. **Groq API Rate Limits:** Hosted judging traffic shares project-level Groq token/request rate limits. Burst traffic hitting Groq limits triggers honest `"AI unavailable"` degraded mode (`ai_status = 'unavailable'`) with sanitized error messaging while preserving deterministic findings.
8. **Python and JavaScript Offset Semantics & Ambiguous Duplicate Fallback:** [`ai-service/main.py`](../ai-service/main.py#L137-L148) now emits JS-compatible **UTF-16 code-unit offsets** and tracks repeated LLM quotes via `cursor_by_quote`. If legacy stored rows contain shifted Unicode offsets where duplicate substrings create ambiguity, [`resolveHighlightSpan()`](../web/lib/validators/review.ts#L417-L474) and [`applyAcceptedEditsToDocument()`](../web/lib/validators/decision.ts#L144-L204) refuse to guess and skip unsafe preview replacement (`skippedUnmatchedCount`) rather than mutating the wrong phrase.
9. **Single-Instance In-Memory Rate Limiters:** [`FixedWindowRateLimiter`](../web/lib/server/rate-limit.ts#L20-L89) guards `/login`, `/api/documents`, `/api/review`, and `/api/suggestions/[id]/decision` per serverless/Node instance; multi-instance distributed rate limiting (e.g., Upstash Redis) is deferred to Round 3.
10. **Asymmetric vs Symmetric Supabase JWT Caching:** [`getVerifiedClaimsUser()`](../web/lib/supabase/claims.ts#L137-L165) caches public JWKS in-memory for zero-RTT verification on asymmetric JWT Supabase projects and safely falls back inside `@supabase/auth-js` `getClaims()` when using symmetric HS256 JWT secrets (still making 1 Auth validation request on symmetric keys until migrated to asymmetric signing keys).
11. **Live Production `next start` Document-Route Viewport Check Deferred to `USER-RUN`:** After remediation, 24/24 viewport checks across `/`, `/login`, `/dashboard`, `/knowledge`, `/documents/new`, and `/404` plus `HTTP 404` invalid/missing document UUID probes passed on clean seeded state; live persisted `/documents/[id]` and `/documents/[id]/history` UI checks require saving a review draft during `USER-RUN` live DB verification.
12. **Input Scope, Read-Only Preview & Unbuilt Features:** Submitted content is capped at `6,000` characters (`MAX_DOCUMENT_CONTENT_LENGTH = 6000`). `"Preview final text"` is read-only clipboard copy and does not overwrite the stored draft. PDF/DOCX ingestion, image/logo checks, analytics dashboards, comments UI (`comments` table exists in schema only), document editing/versioning (`version = 1`), reviewer assignment, and knowledge CRUD UI are **not built**.
