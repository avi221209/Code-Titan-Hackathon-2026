## 3. Explicitly NOT Built (Out of Scope / Not Implemented)

The following capabilities do **not** exist in BrandGuardian today:

- **PDF / DOCX ingestion:** Only plain UTF-8 text up to `6,000` characters pasted or loaded into `/documents/new` is supported. No file upload, PDF parser, or DOCX parser exists.
- **Image or logo checks:** No image upload, OCR, brand-color extraction, or visual/logo compliance checking exists.
- **Analytics UI:** Although `review_decisions` and `audit_events` capture raw rows, no charts, override/rejection analytics views, or rule-health dashboards exist.
- **Comments UI / API:** A `public.comments` table exists in `0001_schema.sql` (hardened with composite FK `(workspace_id, document_id)` in `0004`), **but no API routes or UI components exist** to create, list, or view comments.
- **Document Editing / Re-Versioning & Reviewer Assignment:** `documents.version` remains `1` on all drafts (no document content editor or version increment workflow), and there is no `assigned_to` queue or notification workflow. Any `approver`, `manager`, or `admin` workspace member can decide suggestions.
- **Distributed Redis Rate Limiting:** In-memory fixed-window limiters (`web/lib/server/rate-limit.ts`) guard individual Node/serverless instances cleanly, not cross-region serverless bursts without external store backing.
- **Additional unbuilt surfaces:** No `/documents` list index route (only **Recent Documents** on `/dashboard`), no workspace knowledge editor UI (`/knowledge` is read-only), and no document deletion workflow.
